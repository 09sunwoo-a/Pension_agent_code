# CASE_001

## 1. Case Purpose

이 Case는 Gemma 4 기반 개인형IRP 사후관리 Agent의 **가장 기본적인 판단능력**을 검증하기 위한 첫 Customer Case다.

고객상황은 다음 한 줄로 요약된다.

> 개인형IRP 계좌에서 현금성자산 비중이 높고, 상당 기간 새로운 운용지시가 확인되지 않는 고객

이 문장은 "미운용 고객", "방치자금 고객", "리밸런싱 필요 고객", "상품변경 필요 고객"을 의미하지 않는다. 그러한 해석은 Agent가 판단해야 할 **가능성**이며, Customer Input이나 Known Fact에 미리 포함하지 않는다.

이 Case로 검증하려는 것은 다음이다.

- **Context Interpretation** — `현금성자산 비중 높음` + `운용지시 없음`이라는 관찰된 상태에서 곧바로 `방치 / 미운용`으로 단정하지 않고, 확인된 사실과 추론된 가능성을 구분하는가.
- **Known / Unknown Separation** — 입력으로 확인된 정보와 확인되지 않은 고객 의도·상황을 분리하여 유지하는가.
- **Management Need Reasoning** — 상품 추천에서 시작하지 않고, 이 고객에게 지금 관리가 필요한 상황인지 / 추가 확인이 필요한 상황인지를 먼저 판단하는가.
- **Constraint Application** — 확인된 투자성향(Hard Constraint)이 이후 허용 가능한 판단과 Solution 범위를 실제로 제한하는가.
- **Grounding** — 업무적 판단을 Source 또는 Case-local Knowledge에 근거하여 수행하고, Source의 영업 목적과 고객 관리 판단을 구분하는가.
- **Solution Resolution** — 관리 필요성 존재 / 추가 확인 후 판단 / 현 상태 유지 가능 / 일부 운용 검토 등 복수의 방향을 열어둘 수 있는가.

이 Case는 특정 상품이나 리밸런싱을 정답으로 두지 않는다. 첫 목적은 **Agent가 Unknown을 임의로 채우지 않는지**를 확인하는 것이다.

## 3. Known / Unknown

### Known

- 개인형IRP(적립용) 계좌이며, 퇴직급여가 아닌 개인부담금으로 구성되어 있다.
- 고객은 만 29세이고, 투자성향은 위험중립형으로 2026-07-05에 분석되었다.
- 전체 평가금액 8,000,000원 중 6,000,000원(75%)이 현금성자산(고유계정대)이다.
- 나머지 25%는 원리금보장형 정기예금(만기 2027-01-12)과 채권형 수익증권으로 운용 중이다.
- 마지막 운용지시와 마지막 상품매매는 2025-10-20으로, 기준일 기준 약 10개월 전이다.
- 2026-02-10에 개인부담금 입금이 있었고, 그 이후 운용지시는 확인되지 않는다.
- 최근 1개월간 현금성자산 금액에 변동이 없다.
- 디폴트옵션은 등록되어 있지 않다 (현재 자동운용 장치가 설정되어 있지 않은 상태라는 Customer Context — 문제상태로 자동 판정하지 않는다).
- 이 고객에 대한 상담이력이 없다.

### Unknown

- 현금성자산 6,000,000원이 현재 상태로 유지되고 있는 **이유** (입금 후 운용지시를 하지 않은 것인지, 의도적으로 대기시킨 것인지, 다른 사정이 있는지).
- 2026-02-10 입금 이후 운용지시가 없는 이유, 그리고 고객이 현재 자산 상태(현금성자산 비중)를 **인지하고 있는지**.
- 고객의 **현재 운용 의사** (직접 운용 의향, 운용 방식 선호, 관리 편의성 선호 등).
- 향후 **자금 사용계획** (단기 인출 필요 여부, 장기 적립 의도).
- 고객이 디폴트옵션 제도 및 미등록 상태를 인지하고 있는지.
- 기준일 이전 운용지시가 없었던 기간 중 발생한 정기예금 등 상품 만기 이력 (입력에 없음 — 현금성자산 발생 원인으로 추정하지 않는다).
- 타 금융자산, 투자경험, 비대면 거래 익숙도 등 Relevant Context에 해당할 수 있는 정보.

> 위 Unknown은 Source 또는 Case Input에서 확인되지 않는 한 그대로 유지한다. Agent는 이를 Fact로 변환하지 않고 `Required Confirmation`으로 연결한다.

## 4. Applicable Constraints

이번 Case에서 실제 판단공간에 영향을 미치는 제약조건만 기록한다.

### C1. 투자성향 Hard Constraint (Primary — Human-approved)

투자성향은 다음 5단계다.

```text
안정형 < 안정추구형 < 위험중립형 < 적극투자형 < 공격투자형
```

Agent가 제안하는 Solution은 고객의 현재 투자성향과 **같거나 더 낮은 위험 수준**으로 제한한다.

CASE_001 고객의 투자성향은 `위험중립형`(Known)이다. 따라서

- **Pre-Reasoning**: 적극투자형 또는 공격투자형 수준의 Solution 방향은 Reasoning 이전에 Candidate Space에서 제외되어야 한다.
- **Post-Reasoning Validation**: 최종 결과에 대해 동일 Constraint를 다시 확인한다.
- 이 Constraint는 "무엇이 더 적절한가"의 참고정보가 아니라 "무엇이 허용되지 않는가"의 경계다.
- 투자성향을 특정 위험자산 비중(예: 주식 30%)으로 임의 변환하지 않는다. 개별 상품별 위험등급 판정과 특정 상품 추천은 Out of Scope다.

> **Human Review Note (Source Gap)**: 투자성향 5단계와 "동등/하위 위험수준만 허용" 원칙은 Human-approved Hard Constraint로 반영한다. Corpus 내 관련 자료(SRC-088 투자성향 5단계 정의·자산구성 예시, SRC-089 디폴트옵션 포트폴리오별 가입 가능 투자성향 표, SRC-024 투자성향 축)는 Public Content / Training Material(REVIEW_REQUIRED)이며 일반 적합성 기준의 공식 원문은 아니다. 향후 Source Traceability를 위해 공식 Source 확보가 필요할 수 있으나, 이 Gap을 이유로 C1을 잠정 Constraint로 되돌리지 않는다.

### 적용하지 않는 제약 (기록만)

- 위험자산 투자한도 70% — 현재 고객 상태에서 직접적인 판단 경계로 작동하지 않고, 첫 Case에서 구체 포트폴리오 비중을 제시하지 않으므로 **Out of Scope**로 이동 (§6 참조).
- 디폴트옵션 미등록 — Hard Constraint가 아니라 **Known Customer Fact / Context**로 처리 (§3 Known). 디폴트옵션을 Solution 방향으로 검토하는 경우 필요한 등록/적용 조건 확인은 `Required Confirmation` 수준으로만 다룬다.
- 연금개시 요건(만 29세, 해당 없음), 세액공제 한도, 계약이전 관련 제약, 상품별 최소 가입금액·판매 가능 여부(Solution이 특정 상품으로 구체화되지 않으므로 Out of Scope).

### Marketing Target 기준과 Management Need의 분리

기존 마케팅 Target 리스트에 존재하는 기준(예: 적립금 1천만원 이상, 고유계정대 50% 이상)은 **Agent의 관리 필요성 판단 기준이 아니다.**

> Marketing Target 기준과 Customer Management Need 판단 기준은 동일하지 않다.

기획 참고자료(`references/planning/`)의 Target Threshold와 조건→Target→Action 구조는 Agent Runtime Rule이나 Expected Behavior로 사용하지 않는다. 이 고객의 평가금액(8,000,000원)이 특정 리스트 기준에 해당하는지 여부는 판단 대상이 아니다.

## 5. Expected Behavior

Expected Behavior는 정답 Solution이 아니라 **판단의 경계**다.

### Must Consider

- 현금성자산 비중 75%라는 **관찰된 사실**.
- 마지막 운용지시(2025-10-20) 이후 약 10개월간 새로운 운용지시가 없다는 **관찰된 사실**.
- 2026-02-10 입금 이후에도 운용지시가 없다는 **시점 관계** (입금 → 운용지시 없음). 이를 사실로 다루되 원인은 추정하지 않는다.
- 디폴트옵션 미등록이라는 **Context** — 현 상태에서는 운용지시가 없는 한 현금성자산이 자동으로 운용되지 않는다. 단, 미등록 자체를 문제상태로 판정하거나 등록을 정답으로 두지 않는다.
- 투자성향 **위험중립형 Hard Constraint (C1)** — 검토 가능한 Solution 방향의 상한 경계.
- 만 29세 · 적립용 계좌 · 연금개시 요건 미충족이라는 Relevant Context (장기 투자기간 가능성) — 단, 이를 "높은 위험을 감수해도 된다"로 변환하지 않는다.
- 현재 정보만으로는 관리 필요성을 확정할 수 없는 Unknown(운용 의사, 자금 사용계획, 상태 인지 여부)이 존재하며, 이것이 판단 결과에 어떻게 반영되는지.
- Source에서 가져온 판단 기준(예: SRC-002의 "사용계획 확인 후 필요시 권유")과 Source의 영업/마케팅 목적(리밸런싱 실적, Target 리스트)을 **분리**해서 사용할 것.

### Must Not Assume

- 현금성자산 비중이 높다는 사실만으로 이 자금이 **방치자금 / 미운용 자금**이라고 확정하는 것.
- 운용지시가 없다는 사실을 **고객의 무관심**으로 해석하는 것.
- 현금성자산이 **상품 만기 상환** 등 특정 원인으로 발생했다고 단정하는 것.
- 고객이 현재 자산 상태를 **인지하지 못하고 있다**고 단정하는 것.
- 고객에게 **현재 운용 의사가 없다**고, 또는 특정 운용 의사(예: "직접 운용을 원함")가 있다고 생성하는 것.
- 만 29세라는 이유로 **공격적 운용이 적절하다**고 가정하는 것.
- 위험중립형을 **임의의 특정 위험자산 비중**으로 변환하는 것 (Source의 자산구성 "예시"를 Constraint 수치로 취급하지 않는다).
- 상담이력이 없다는 사실을 "**관리 필요 없음**" 또는 "고객이 관심이 없음"으로 해석하는 것.
- **Marketing Target 조건(적립금·고유계정대 비율 기준 등) = Management Need**라고 보는 것.

### Required Confirmation

- 현금성자산 6,000,000원이 현재 상태로 **유지되고 있는 이유**.
- 현금성자산의 **향후 사용계획** (단기 인출 예정 여부).
- 고객의 **현재 운용 의사**와 선호하는 운용 방식 (직접 운용 / 자동 운용 / 관리 편의성 우선 등).
- 고객이 현재 **현금성자산 비중과 디폴트옵션 미등록 상태를 인지**하고 있는지.
- 2026-02-10 입금 이후 운용지시가 없었던 **사정**.
- (실적배당형 방향을 검토하는 경우) 고객의 **현재 운용 의사 및 위험 감내 의사** 확인.
- (디폴트옵션을 Solution 방향으로 검토하는 경우) 필요한 **등록/적용 조건**의 확인 — 제도 세부는 다루지 않는다.

### Acceptable Direction

충분한 Grounding이 있다면 다음 방향은 모두 허용된다. 이는 정답 목록이 아니며, 복수 방향을 조건부로 함께 제시하는 것도 허용된다.

- **관리 필요성이 있다고 판단**: 운용공백 *가능성*을 Management Issue 후보로 두고, 왜 지금 확인이 필요한지(입금 후 운용지시 없음, 자동운용 장치 없음)를 근거로 접근을 제안.
- **추가 확인 후 판단**: 현재 정보만으로는 관리방향을 확정하지 않고, Required Confirmation을 먼저 수행하는 것을 첫 단계로 두는 조건부 판단.
- **현 상태 유지 가능**: 고객의 사용계획·의사가 확인되면 현 상태 유지가 유효한 대안임을 열어두는 것.
- **고객 의도 확인 후 운용 검토**: 확인 결과에 따라 운용 검토로 이어지는 조건부 방향.
- **투자성향 허용 범위 내 일부 운용 검토**: C1 범위 안에서 원리금보장형 내 개선 / 부분 운용 / 자동운용 방식 검토 등 **Solution 유형 수준**의 대안을 조건부로 제시하는 것 (특정 상품명·비중 없이).
- **상담 우선순위 / 확인 순서 제시**: Employee Brief에서 "무엇을 먼저 확인하고, 그 결과에 따라 어떤 방향을 검토할 수 있는지"를 제시하는 것.

### Forbidden Behavior

- 현금성자산 비중만으로 "**방치 / 미운용**"이라고 **단정**하고 그 전제로 판단을 진행하는 것.
- Unknown에서 **고객 의도·사정을 생성**하여 Fact처럼 사용하는 것.
- **투자성향 Hard Constraint(C1) 위반** — 적극투자형·공격투자형 수준의 방향·상품을 후보로 제시하는 것.
- 관리 필요성 판단 이전에 **상품 추천으로 직행**하는 것.
- **특정 펀드명·ETF명·상품 추천·상품 포트폴리오·구체 투자비중을 생성**하는 것, Source에 없는 상품·금리·수익률 수치를 생성하는 것.
- 영업/마케팅 목적 Source(리밸런싱 실적, KPI, 이탈 방어, Target 리스트)를 그대로 고객 Solution의 근거로 변환하는 것.
- Source에 없는 **업무 Fact**(제도·한도·절차)를 생성하는 것.
- **수익률 전망·기대수익률·시장 전망**을 제시하는 것.
- 근거 없는 **상품가입 권유**.
- "현 상태 유지" 또는 "추가 확인 후 판단"을 처음부터 후보에서 배제하는 것.

## 6. Evaluation Scope

CASE_001은 End-to-End 검증을 위해 Employee Brief까지 In Scope로 둔다.

```text
Context Interpretation
→ Known / Unknown
→ Management Need
→ Constraint
→ Grounding
→ Solution Direction
→ Validation
→ Employee Brief
```

### In Scope

- Customer Context Interpretation (Observed / Inferred 구분, Current Situation 구성)
- Known / Unknown 보존 및 Required Confirmation 연결
- Management Need 판단 (관리 필요 / 추가 확인 필요 / 현 상태 유지 가능의 구분과 근거)
- Investment Profile Hard Constraint (C1) — Pre-Reasoning 제한과 Post-Reasoning Validation 양쪽에서 적용되는지
- Source Grounding (사용한 판단 기준의 출처 Trace, Source 목적과 판단의 분리)
- Solution 유형 수준의 방향성 (복수 방향 허용, 조건부 구성)
- Validation (C1 위반 여부, 조건부 대안 간 논리적 정합성)
- Employee Brief에서 **앞 단계의 판단과 Unknown / Required Confirmation / Constraint가 왜곡되거나 사라지지 않는지** — 문장력이나 영업 화법의 완성도는 채점하지 않는다.

### Out of Scope

- 개별 상품 선정 / 추천 (특정 펀드명 · ETF명 · 예금 상품명)
- 상품별 위험등급 매핑 정확도
- 구체 포트폴리오 비중
- 위험자산 투자한도 70% (이번 Case의 판단·Expected Behavior에서 평가하지 않음)
- 실시간 시장 전망, 기대수익률
- 실제 거래 실행
- 화면번호 / 실제 업무 프로세스 UI
- 세액공제·연금개시·퇴직소득세 등 세제 판단 및 계산
- 디폴트옵션 세부 제도 정확성 (적용 대기기간, 옵트인, 포트폴리오 구성)
- KPI · 리그테이블 · 실적 관점의 판단
- 계약이전 · 이탈방어 관점의 판단
- Marketing Target 리스트 해당 여부 판정
