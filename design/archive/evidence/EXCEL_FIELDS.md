## 2. [룰베이스] 조건식에 등장하는 고객 데이터 필드명 (정규화 필드)

## 3. [분리 절] Badge / Target / Action / 추천행동 성격의 열

> **판단 근거 사용 금지.** 아래 열들은 기획자·본부가 미리 만들어 둔 판단결과(세그먼트 분류, 권유 문구, 캠페인 액션)로, 고객 상태 데이터가 아니다. README 명시: Customer→Action Rule·Expected Behavior 정답·Runtime Rule Base로 가져오지 않는다. Evidence Pack에서는 **⑨ Existing Bank Signals 섹션의 "형태(어떤 모양의 시스템 태그/캠페인 분류가 입력으로 들어올 수 있는가)" 참고로만** 사용 가능하며, §1~§2의 고객 상태 필드와 절대 섞지 않는다.

## 4. 관찰 요약 — Excel에는 있는데 기존 Golden Case(cases/GC-*) 입력에 없을 법한 필드

기존 GC 케이스의 Customer Input(예: GC-01 §2)과 대조한 결과:

1. **동연령대 비교 통계 일체** (07_PEER_COMPARE: 동연령대평균/상위1%수익률, 상위1% 원리금보장비중·펀드TOP3·ETF TOP3) — GC-05에 부분 언급 흔적만 있고 표준 입력 블록으로는 없음. 넣는다면 고객 상태와 분리된 참고 Context로.
2. **상품 단위 고객보유수익률 vs 상품 최근1년수익률의 구분** (03_PRODUCTS) — GC 입력은 계좌 단위 수익률만 제공. "펀드 자체 수익률"과 "이 고객의 보유손익"을 분리하는 필드는 판매중단펀드·손실 케이스 진단에 유용.
3. **연도별 납입 이력** (2023/2024/2025년IRP납입액, 당해년도연금저축납입액, 당해년도세액공제인정납입액) — GC 입력은 세액공제 잔여한도를 아예 "제공하지 않는 정보"로 빼는 경우가 많고, 연도별 납입 시계열은 어디에도 없음. ③ Timeline·④ Whole-Asset의 원형.
4. **활동 카운트·플래그류** (최근1년상품매매횟수, ETF/수익증권 과거매매이력여부, 최근1개월고유계정대증감액) — GC는 "최근 운용지시일" 정도만 사용. 매매 빈도·현금 유입 급증(±1.7억) 같은 수치형 행동 신호는 ⑤·이탈관찰 케이스에 필요.
5. **디지털 행동로그 필드** ([룰베이스]의 ETF_화면조회일/시세조회횟수, 배너 이벤트_클릭, 세미나_신청) — GC 입력엔 "스타뱅킹 이용 여부" 수준만 존재. ⑦ Digital Signals 섹션의 구체 필드 후보는 이 파일에만 있음.
6. **고객 등급·식별 메타** (KB스타클럽등급, 관리점, KB-PIN, 고객명) — GC는 의도적으로 제외("제공하지 않는 정보")하는 관행이 있으므로, Evidence Pack에서 포함 여부를 명시적으로 결정해야 함.
7. **KB-PIN 키 구조의 시트 간 조인 방식** (BASIC/SUMMARY/PRODUCTS[]/ACTIVITY/TAX_ISA/PENSION/상담이력[]) — 단일 서술형 입력이 아닌 "요약 스냅샷 + 상품 배열 + 이력 배열" 구조 자체가 Evidence Pack 스키마 설계에 참고할 형태.
