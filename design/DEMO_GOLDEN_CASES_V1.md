- Status: DRAFT v1 (2026-09-01)
- 작업 성격: **Demo Scenario Design** — Agent Logic 평가·개선 아님. Knowledge → Solution → Brief → RAW INPUT 순서의 역설계.
- 근거 Knowledge 스냅샷: `knowledge/` Registry 2026-08-31 등록분 (OK-001~017 / PRD-001~022 / HT-001~006 / TALK-001~012 / SCR-001~023 / KG-001~008 / SC-001~003)
- RAW Schema Source of Truth: `prototype/mock/MOCK_001_raw.json` (블록: case_id / base_date / customer / irp_account / balance_snapshot_30d / transactions / trades_12m / digital_behavior / wider_context / crm_notes)

# 1. 작업 목적

현재 Repository에 이미 구축된 기반지식(공식 제도 지식·상품 Registry·Hot Tip·상담화법·업무화면)을 **서로 결합했을 때 가장 인상적인 직원용 Brief(S1~S5)** 를 보여줄 수 있는 가상의 고객 Case 5종을 기획한다.

- 현재 Agent Logic(Retrieval·Prompt·Validator)이 이 Brief를 재현할 수 있는지는 **평가하지 않는다.**
- 단, Brief의 모든 제도·상품·화법·화면 내용은 **현재 Knowledge Registry에 실존하는 항목에만 Grounding**한다. Knowledge에 없는 내용은 만들지 않는다.
- RAW INPUT은 현재 확정 Schema를 100% 그대로 따르며, 판단 라벨·고객 의도를 심지 않고 **관찰 가능한 사실만** 담는다.

### RAW INPUT 작성 공통 규칙 (본 문서 5개 Case 전체 적용)

1. 최상위 블록·필드는 `MOCK_001_raw.json`과 동일. 신규 최상위 필드 추가 없음.
2. `base_date`는 5개 Case 모두 `2026-09-01`로 통일.
3. `crm_notes`는 MOCK_001에서 빈 배열이라 요소 구조가 미정의 상태 — 본 문서에서는 관찰 사실 최소 구조 `{date, channel, note}`만 사용한다(신규 최상위 Block 아님, 기존 Array 내부 합성값). note에는 **판단·의도 라벨 없이 실제 발화/기록 문면만** 담는다.
4. 타행 ISA·퇴직금 통장 수령 등 **IRP 계좌 밖 사실은 신규 필드를 만들지 않고** crm_notes(과거 상담 발화 기록)·digital_behavior(앱 조회 행동)·wider_context(기존 키)로만 표현한다.
5. 화면번호는 Brief의 S5에만 노출한다(G3 — EMPLOYEE_BRIEF_SPEC v2).
6. 금지어("방치" 등)·Bank Objective 추천사유(HD-7/G4)는 Brief 전 섹션에서 배제한다.

### KC-10. 투자성향 상향 재분석 × 성향=상한 해석 × 안내 원칙
