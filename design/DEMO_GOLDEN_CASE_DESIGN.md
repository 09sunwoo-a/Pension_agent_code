# DEMO Golden Case Design — 지식베이스 역설계 시연 고객 5선

- Status: DRAFT (2026-09-01, 시연 준비용)
- 목적: 현재 Repository의 Knowledge(OK/PRD/HT/TALK/SCR/KG/SC)를 먼저 탐색하여 **지식이 한 고객 상황에서 결합될 때 Agent 가치가 최대화되는 조합(Knowledge Cluster)** 을 발견하고, 그 조합이 자연스럽게 발생하는 시연용 고객 Case를 역설계한다.
- 준거: `design/EMPLOYEE_BRIEF_SPEC.md` v2(G1~G4, F-013 원칙), `cases/FAILURE_MAP.md`, `knowledge/*` Registry 전체. 이 문서의 모든 Knowledge/상품/화법/Tip/화면 ID는 **현재 Registry에 실존하는 항목만** 인용한다.

# 1. 시연 Case를 어떻게 찾았는가 (역설계 원칙)

기존 GC-01~25는 "검증하고 싶은 Failure/Capability"에서 출발했다. 이번 시연 Case는 반대 방향으로 설계했다.

1. **Registry 전수 탐색** — OK-001~017(공식지식), PRD-001~022(상품), HT-001~006(Hot Tip), TALK-001~012(화법), SCR-001~023(화면), KG-001~008(Gap), SC-001~003(Conflict)을 읽고, 서로 참조 관계가 이미 존재하는 항목 묶음을 추출했다. (예: OK-001은 HT-004를 T3 보강 근거로, SCR-014·015를 실행 화면으로 이미 지목하고 있다 — 이런 "원천이 스스로 이어 놓은 사슬"이 가장 자연스러운 Cluster다.)
2. **Cluster 성립 조건** — `Event/Opportunity → 공식지식 → Solution → 상품 → 화법 → Tip → 화면` 사슬의 각 단계가 실존 ID로 채워지는지 확인했다. 한 단계라도 Registry에 없으면 그 사실을 Gap으로 명기했다(§20 사실성 원칙).
3. **고객 역설계** — 성립한 Cluster에 대해서만, 그 Cluster가 "자연스럽게 발동"되는 관찰 가능 데이터(Fact/Signal/Unknown 구분)를 가진 고객을 설계했다. 고객 Input에는 정답·의사·니즈를 심지 않았다(§5 원칙). 기존 Case(GC-13 ISA, GC-22 복수시한 등)와 주제가 겹치는 경우 **관리 목적·발견 구조·분기 설계를 다르게** 하여 신규 설계했다.
4. **Failure History 반영** — F-001(Unknown→사실 승격), F-005(Action 편향), F-013(S4 확실성 인플레이션), CRM 과신, Digital Signal→Intent 승격 등 실측 오판 유형을 각 Case의 "반드시 피해야 할 오판"에 반영했다.

# 2. Knowledge Cluster 후보 (10개)

각 Cluster는 실존 ID만 인용한다. `⚠`는 해당 단계가 T3 단독이거나 Gap임을 뜻한다.

## CL-01 — 타행 ISA 만기 × IRP 전환입금 × 추가 세액공제

- **발견 가능한 고객 Event**: 타행 ISA 만기 임박 (Whole-Asset Context에서만 보임 — IRP 화면에는 없음)
- **공식지식**: OK-001(60일 시한·전부/일부·연 1,800만 한도와 별도·전환액 10% 최대 300만 추가공제), OK-008(세액공제 구조·결정세액 조건 — 실효는 별도 확인), OK-017(상품 판매가능 확인 경로)
- **상품/운용**: PRD-004(마이다스 기본 TDF, 4등급)·PRD-010·PRD-011(혼합 4등급)·PRD-005·PRD-006(채권 5~6등급)·PRD-018(GIC 라인업)·PRD-021(DO 포트폴리오) — 전환 확정 후 Branch에서만
- **화법**: ISA 전용 T2 화법은 Registry에 없음 ⚠ — TALK-007("먼저 자금 계획을 확인하라" 원칙)·TALK-006(사용계획 질문형 오프닝)의 **구조** 차용
- **Hot Tip**: HT-004(ISA 만기자금 IRP 전환 마케팅 — 60일·증빙 불필요·이월공제, T3)
- **화면**: SCR-015 [04-10-099](저축종류 83-만기 ISA 전환 → 전환 가능액), SCR-014 [01-12-213](거래구분 'ISA 만기자금 입금' — 입금가능금액 자동조회), SCR-005 [06-12-151](납입한도), SCR-004 [04-12-17A](상품조회)

- **금지**: 표시금리 최고 상품 단순 추천 / 예금자보호 5천만(구자료) 인용(SC-001) / 저축은행 개별 상품명 생성.

### B-8. 상담 흐름 / 화법

### B-10. 실제 실행화면

- S3: 개시 시점 확인 결과별 2분기 + 공통 확인 사항.
- S4: 표시금리 함정 설명 화법 + 4분기.
- S5: TALK-009·계산기·화면 5종.

### B-12. 시연 하이라이트
> "금리 높은 걸로 다시 넣어주세요"로 끝날 수 있는 만기 상담에서, Agent는 금리 표시 기준·매수한도·예금자보호·연금지급 가능 여부·개시 계획 정합이라는 5개 축을 꺼내 온다.
> 실명 GIC 라인업과 저축은행 한도 규칙이 붙고, "저축은행 개별 상품은 지식에 없으니 화면에서 확인하라"는 정직한 경계까지 보여준다.
> 상품 연결이 가장 구체적이면서도, 추천이 아니라 '비교의 축'을 제공하는 Agent라는 인상을 남긴다.

### B-13. 반드시 피해야 할 오판
- CRM의 "60세 개시" 발언을 확정 계획으로 승격(GC-20 유형).

### B-14. 왜 Agent인가
비교 축 5개가 전부 다른 Registry(제도·상품·화법·Gap)에 흩어져 있고, 어떤 축이 이 고객에게 유효한지가 개시 계획이라는 Unknown에 걸려 있다. Rule로는 "만기 D-21 알림"까지만 가능하다.

## DEMO-C — "급여계좌에 들어온 퇴직금, 60일이 지나기 전에" (CL-02)

### C-1. Case 이름
퇴직금 1.8억 일반통장 수령 D+14 · IRP는 소액 적립계좌 — 과세이연 재입금 기회와 5-Step 절차

### C-4. Agent가 발견해야 할 핵심

### C-9. 영업점 Tip
- HT-001: 니즈가 여러 개인 고객은 부수 니즈부터 정리 후 퇴직금 건 집중(사례 참고, T3).

### C-10. 실제 실행화면

- SCR-023 [04-12-648] — 과세이연계좌신고서 출력 / SCR-008 [04-12-644] — IRP 입금내역 출력.

### C-11. 기대 S1~S5 Brief

- S3: 3분기 조건부. S4: TALK-006 원문 화법. S5: 5-Step ↔ 화면 매핑.

### C-12. 시연 하이라이트
> IRP 화면만 보면 아무 일도 없는 고객이다. Agent는 수신계좌의 '퇴직급여' 입금을 발견하고, 60일 환급 제도와 직원이 외우기 힘든 5-Step 절차·서류·화면을 통째로 조립해 온다.
> 그러면서도 첫 화법은 권유가 아니라 "바로 쓰셔야 해서 받으신 걸까요?"라는 계획 질문이다.
> 제도(2종)+과세+화법(2종)+Tip+화면(6종)이 한 Case에 결합되는, 지식 융합의 대표 시연.

### C-13. 반드시 피해야 할 오판
- 잔액 유지 관찰을 "쓸 계획 없음"으로 승격(G2 의미 승격 통제).

- 입금 순서 오류 안내(과세이연정보 등록 전 입금 — OK-014 Step 순서 보존).

### C-14. 왜 Agent인가

### D-6. 기대 관리 Solution
- **[자동매수 수용]** 정상 작동임을 확인시켜 주고 종료 — 개입 불필요 Branch를 명시적으로 유지(F-005 방지).
- **[직접 운용 의향 확인 시]** 실행 전 대기자금 처리 경로 안내. 성향 범위(4~6등급) 내 유형 수준 선택지 + 위임형(옵트인 — 대기 없이 즉시 운용 가능) 병행 안내.
- **[다른 DO를 원하면]** DO 변경은 등록 변경과 보유상품 매수의 2단계 구조(OK-005) 사실 안내.

### D-7. 상품 연결
- 직접운용 Branch에서만: PRD-004(TDF 4등급)·PRD-010·PRD-011(혼합 4)·PRD-005·PRD-006(채권 5~6)·PRD-018(GIC)·PRD-021(알파드림·뿔려드림 — 위험중립 가입 가능). 모두 sellable 미확인(KG-008) → [04-12-17A] 확인 전제. TDF 조회 이력은 "관심 소재"로만 언급 가능, 추천 근거 아님.

### D-8. 상담 흐름 / 화법
1. 시작: "다음 주에 대기 중인 자금이 지정해 두신 디폴트옵션으로 자동 운용될 예정이라 미리 안내드리려 연락드렸다" — 사실 통지형 오프닝.
2. TALK-008 코멘트: "국민은행이 만든 절차가 아니라 법에 따라 모든 금융기관이 운영하는 제도" — 불안 해소.
3. 의향 확인: 그대로 둘지 / 직접 고를지 / 지정 상품을 바꿀지.
4. 분기: [거부감] → TALK-008 3단계(권리→국가 검증→주도권) / [망설임] → TALK-010 "일부만 변경해 보시고, 마음에 안 드시면 다시 바꾸실 수 있습니다" / [초저위험 그대로] → 존중(성향과 무관하게 정당 — OK-006) / [직접 운용] → 유형 확인 질문(기간·목적) 후 후보.

### D-9. 영업점 Tip
- HT-006: DO 등록·변경과 대기자금 교체매매는 별개 거래이므로 세트로 안내(T3 — 실행 절차는 공식 화면 기준 확인).
- 재만기 유의: 동일 상품 재만기 시 6주 대기 없이 익영업일 적용(OK-005, 연수교재 단일 근거 — 확정 화법 금지).

### D-10. 실제 실행화면
- SCR-002 [04-12-640] — 거래구분 '사전지정운용제도 상세조회'로 실행예정내역 확인(상담 전 확인).

### D-11. 기대 S1~S5 Brief
- S1: 실행예정일 D-7 Fact + 조회 신호는 "탐색 행동, 의사 미확인"으로.
- S2: 포인트 = 자동실행 전 의사확인 접점. [고객 확인] 인지 여부·선호 / [직원 확인] 실행예정내역 최신 조회.

### D-12. 시연 하이라이트
> Agent가 "지금 문제가 있다"가 아니라 "7일 뒤 일어날 일"을 화면 조회값으로 짚는다.
> 자동매수를 막지도, 부추기지도 않는다 — 고객의 선택 기회를 만드는 것이 관리라고 판단한다.
> 거부감·망설임·수용·직접운용 각각에 실존 화법(TALK-008/010)이 붙고, 직원은 확인 화면과 처리 화면을 그대로 받는다.
> S4·S5가 가장 돋보이는 Case — "말할 내용과 누를 화면"이 완성돼 나온다.

### D-13. 반드시 피해야 할 오판
- "방치된 자금" 표현(deterministic 금지어 — F-001 실측 재발 지점).
- 조회 이력을 "직접 운용 원함"으로 승격 / 초저위험 지정을 "성향 대비 부적절"로 프레이밍(HD-2 위반 — GC-04/09 검증 축).
- 6주 시계를 스스로 기산해 실행일 단정(실행예정일은 화면 값 인용).
- 재만기 T+1을 확정 제도 사실로 화법 승격(단일 근거 — F-013).

### D-14. 왜 Agent인가
"만기 후 N주 경과 → 알림" Rule은 이 Case의 절반이다. 나머지 절반 — 자동실행이 문제가 아니라는 판단, 성향-DO 관계의 올바른 해석, 신호를 의사로 승격하지 않으면서 3분기를 여는 상담 설계, T3/단일 근거 지식의 화법 통제 — 는 맥락 판단이다.

## DEMO-E — "해지하겠다는 고객에게 다른 문을 보여주다" (CL-03)

### E-1. Case 이름
"IRP 해지 절차 문의" 인바운드 · 전세 이사 예정 · 47세 — 중도인출 가능성 확인이 먼저

### E-2. 고객 Briefing
- 만 47세, 위험중립형. IRP 평가 8,000만(세액공제 목적 납입 6년차, 올해 400만 납입).
- 보유: 채권형 펀드 5,000만 + 정기예금 2,000만(만기 2027-02) + 현금성 1,000만.
- 2026-08-28 콜센터 인바운드: "IRP 해지 절차 문의" 접수 기록.
- CRM(같은 통화 메모): "내년 초 전세 이사 예정이라 자금이 필요할 것 같다."
- 재직 중(당행 급여이체 계속 관찰).

### E-3. Raw Data 설계
- **Fact**: 해지 절차 문의 접수 사실(문의≠확정 의사), 보유·납입 이력, 연령.
- **Signal**: CRM 통화 메모(이사 예정 — 계약 체결 여부 불명).
- **Unknown**: 무주택자 여부 / 전세계약 체결 여부·계약일·잔금일 / 필요 금액(전액인지 일부인지) / 세액공제 미신청분 존재 여부 / 해지 의사의 강도.

### E-4. Agent가 발견해야 할 핵심
> 고객이 요청한 것은 해지지만, 필요한 것은 자금일 수 있다. 무주택자 전세보증금은 **중도인출 법정 사유**(OK-015)에 해당할 수 있어, 요건이 확인되면 **전액 해지 대신 필요액만(최대 90%) 인출**하는 경로가 존재한다. 어느 경로든 세액공제 미신청분의 사전 등록(OK-009, [06-12-622])이 세부담에 영향을 주므로 확인이 선행돼야 한다.

### E-5. 필요한 기반지식

### E-6. 기대 관리 Solution
- **[중도인출 사유 요건이 확인되면]** 필요 금액만 세전 기준으로 신청하는 중도인출 경로 안내(잔여 자산은 계속 운용). 신청 가능 시기(계약 체결일~잔금 후 1개월)와 창구 접수·서류를 사전 고지.

- **[공통 선행]** 세액공제 미신청분 확인·등록([06-12-622]) — 어느 경로든 세부담에 영향.

### E-7. 상품 연결
- 없음(상품 권유 비해당 Case — S3에 "이 상담에서 상품 권유는 하지 않습니다" 명시가 정답 형태). 인출 후 잔여 자산 운용은 추후 별도 접점.

### E-8. 상담 흐름 / 화법
1. 문의 응대로 시작 — 해지 절차 안내를 회피하지 않음.
2. 필요 확인: "혹시 필요하신 금액이 정해져 있으실까요? 전액이 필요하신 건지요?"(TALK-012 구조 — 필요액 기준 대안 탐색).
