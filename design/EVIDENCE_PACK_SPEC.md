## 1. 횡단 규칙

1. **`value + as_of`**: 모든 항목에 기준일 또는 발생일. 수치가 출력으로 전달될 때 as_of 동반 유지.
2. **F / A / R / S 라벨**: 직렬화 시 항목 단위 표시. S에는 개념 주석 동봉(§2-⑦).
3. **NULL / 0 / 해당없음 3분**: 값 없음·수량 0·규칙상 대상 아님을 구분, 임의 보완 금지.
4. **판단 완료형 라벨 금지**: "미운용 방치고객"·"이탈위험 고객" 류 없음. TM·캠페인·Badge·LMS 등 Bank Signal은 **입력 자체에서 제외**(결정 2-9).
5. **Missing = Evidence Missing만**(결정 2-11): 스키마에 존재하는 데이터 항목이 해당 고객에게 없으면 NULL/"데이터 없음"으로 명시(고정 스키마). 자금 사용계획·위임 선호 같은 **Decision Variable은 입력 슬롯이 아니다** — Agent가 Required Confirmation으로 도출한다(§5).
6. **과거 상태의 Timeline Fact화 금지**(결정 2-3): 현재 정보에서 과거 상태를 추정해 Event처럼 제공하지 않는다. Timeline에는 원천 시스템에 실존하는 Event만.
7. **데이터 확보 시점 3계층**(결정 1-4): Base Customer Evidence(정기 확보) / Pre-Judgment Enrichment(판단 직전 조회 — 확보 시 출처 표기 후 동봉 가능) / Execution-time Check(실행 직전 직원 확인 — 입력 아님, Next Action·S5 산출물). 화면에 존재한다는 이유만으로 Base로 간주하지 않는다.
8. **Performance Comparison Boundary**(추가 결정 3): 고객 자신의 성과 정보(계좌 수익률·상품별 고객 보유수익률·상품 자체 수익률, 각 as_of/측정기간)는 Customer Performance Context로 **유지** — Customer holding return과 Product return의 의미 차이를 구분 보존한다. 외부 비교기준(동일 유형 비교수익률·Benchmark·대안 상품 Performance)은 Customer Evidence가 아니라 **Reference Data/Knowledge 영역**이며, REV-002에서 실제 필요 없는 데이터를 새로 만들지 않는다. **Peer Comparison(동연령대·상위 고객·상위 1%·유사 고객군 Ranking)은 REV-002 제외 유지.** Performance Comparison은 상황 이해·손익 맥락·선택지 비교·상담 설명의 Supporting Evidence로 쓸 수 있으나 **단독으로 교체·리밸런싱·위험 확대·특정 상품 가입의 Management Need를 확정하는 Trigger가 될 수 없다** — 보유기간·가입시점·자금성격·성향·자산구성·고객 의사/CRM과 함께 해석한다.

| R3 | 세액공제 잔여한도 | **시스템 산출값을 그대로 수신** (O) | 원천 구성요소(기준한도·인정납입액)는 입력 미제공(결정 2-2 삭제)이므로 **전처리에서 자체 계산하지 않는다** — 수신값에 rule_source="시스템 산출"·rule_as_of만 부여 |
| R4 | 위험자산 비중·70% 한도 판정 (+초과분) | 위험자산 분류(적격 TDF·DO 예외 포함) → 비중 → 한도 대조 | **위험자산 분류 기준의 공식 원문 필요** — 확보 전 SRC-077(Hot Tip, 직원 정리) 단독으로 판정 불가(HD-3). Source Traceability Gap으로 기록(§6) |

경계 규칙(유지): "미운용 추정"·"방치"·"관심 있음" 같은 **의미 부여는 전처리 금지**.

## 5. Required Confirmation — 입력이 아니라 Agent 산출물 (결정 2-11)

구 §5의 "Missing 고정 슬롯 14개"는 **입력에서 제거**한다. Human 결정에 따른 재분류:

- **A. Evidence Missing**: 스키마(§2)에 존재하는 실데이터 항목이 해당 고객에서 없으면 NULL/"데이터 없음"으로 제공 (고정 스키마 원칙 유지). 예: CRM 메모 없음, ISA 해당없음, 입금사유 코드 NULL.
- **B. Required Confirmation / Decision Variable**: 자금 사용계획·수령 희망 시점/방식·만기 길이 선호·직접/위임 선호·채널 선호·DO 인지/수용·손실 감내·재취업/추가납입 계획·이전 사유/부분 이전 의향·필요액 세전/세후·금리 비교 희망·H/UH 선호·운용 대상 자금 범위·불만/니즈의 실체·현금성 발생 사유의 고객 설명 — **전수 B로 분류됨(14/14).** 시스템 데이터가 아니라 상담으로만 확인 가능한 Decision Variable이며, Agent가 Evidence와 판단 결과로부터 도출해야 할 영역이다. **입력의 정답 힌트로 제공하지 않는다.**

14개 목록의 보존: 삭제하지 않고 **Golden Evaluation의 Required Confirmation Coverage 준거 목록**으로 이동을 제안한다(F-004 판정 시 Case 유형별 기대 확인 축의 사전) — Step 3 보고 §4에서 확인.
