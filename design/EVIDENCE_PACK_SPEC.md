- **Availability(`Av`) 열은 전부 `?` — 은행 시스템에서 실제 확보 가능한지는 Human만 답할 수 있다. Step 3에서 확정 전에는 어떤 필드도 "시스템 제공"으로 단정하지 않는다.**

표기: 유형 = **F**(Fact: 시스템 직접 확인) / **C**(Calculated: 원천 데이터의 객관 계산값, §4 산식) / **S**(Signal: 행동·간접 단서) / **CS**(Customer-stated). `Δ` = 변화량 제공 대상. 근거 = 대표 Case 또는 Excel 시트.

## 1. 횡단 규칙 (모든 섹션 공통)

1. **`value + as_of`**: 모든 항목에 기준일 또는 발생일. 수치(금리·금액)가 출력으로 전달될 때 as_of 동반 유지(GC-08에서 재생산 실패 관찰).
2. **F / C / S 라벨**: 직렬화 시 항목 단위로 표시. S에는 개념 주석("관심·행동의 Evidence이며 고객 의사를 직접 의미하지 않는다") 동봉 — GC-05에서 라벨링 효과 실증.
3. **NULL / 0 / 해당없음 3분**: 값 없음(NULL)·수량 0·규칙상 대상 아님(해당없음)을 구분하고 임의 보완 금지(룰베이스 코드_거버넌스 차용). 예: "최근 매매일: NULL(이력 없음)" ≠ "매매횟수: 0".
4. **판단 완료형 라벨 금지**: "미운용 방치고객", "ETF 니즈 고객", "이탈위험 고객" 류는 입력 어디에도 없다. Badge/Target은 §9의 격리 형태로만.
5. **Missing 고정 슬롯**(§5): 모든 고객에 동일 슬롯으로 제공 — Case별 선택 제공은 확인 축 힌트가 되므로 금지.
6. **직원 화면 조회값의 동봉 기준**(P1 관찰 7): **판단 전에 필요한 값**([04-12-644] 입금사유, [04-12-354] 위반 표시, [04-12-17A] 특별제공 금리 등)은 조회값으로 입력에 동봉 가능; **실행 전에 필요한 값**([02-12-221] 수령한도, 계산기 결과, [04-12-613] 실제 수수료율)은 입력이 아니라 Next Action("이 화면에서 확인")의 산출물. 경계는 화면 종류가 아니라 필요 시점.
