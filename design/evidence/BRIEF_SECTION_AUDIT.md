# BRIEF_SECTION_AUDIT — 기존 17 GC + CASE_001 출력을 새 Brief 5-섹션 구조로 재독해

- 작성일: 2026-08-31
- 대상: cases/CASE_001 + cases/GC-01~GC-17, 각 Case의 최신 RUN (RUN_002 존재 시 RUN_002, 없으면 RUN_001)
- 근거: 각 RUN 파일의 §3 Interpreted Context / §6 Decision Output / §7 Next Actions(또는 Solution Candidates) / §9 Employee Brief 원문, 및 evals/의 F-001·F-008 지적 위치
- 판정 기준 (새 5-섹션 Target Concept):
  - **S1 고객 상황**: 핵심 간결 + 절제된 해석 허용, 단정 어휘("방치" 등) 금지
  - **S2 핵심 관리 포인트**: "지금 무엇을 관리하는 것이 중요한가" + 바로 아래 "먼저 확인하세요"(Required Confirmation 종속)
  - **S3 추천 운용 방향**: 연령·자금성격·기간·성향 고려, 조건부("의사 확인되면 →"), 필요 시 상품 유형/상품
  - **S4 상담 Point**: 직원의 접근 논리·설명 순서·**실제 화법**
  - **S5 관련 TIP & GUIDE**: 행내 자료 연결(Hot Tip·화면번호·업무 절차·반론 대응·제도 유의사항) + 출처 표기
- 판정 방법: RUN 출력 전체(구조화 판단부 + Employee Brief)를 대상으로 함. "있음"은 해당 섹션 요건의 실질이 존재, "부분"은 일부 요소만 존재, "없음"은 실질 부재.

공통 전제(모든 Case 공통 관찰): 현 출력 스키마는 `current_situation` / `known_facts_used` / `unknowns_or_confirmations` / `management_judgment(+reasoning, must_confirm)` / `next_actions(action·kind·condition·risk_level)` / `employee_brief`(단일 문단)로 구성된다. 새 5-섹션 중 S1·S2·S3의 원재료는 구조화 판단부에 이미 있으나, **Brief는 단일 문단이어서 섹션 구분이 없고**, S4의 "실제 화법"과 S5의 "출처 표기된 행내 자료 연결"은 스키마 자체에 자리가 없다.

9. **[전체] Employee Brief의 섹션 분리**: 현 단일 문단 Brief를 5-섹션 구조로 분리(단일 문단이 조건 탈락(F-008)과 단정 어휘(F-001)의 온상임이 CASE_001·GC-03·GC-12에서 확인됨).

**금지 요소 후보** (실제 발생 사례가 있는 것만):

1. **판정어 "방치"** 및 동계열 단정 어휘 — CASE_001·GC-09·GC-17에서 실제 발생, GC-12 RUN_001에서도 발생 후 제거됨. Unknown이 남아 있는 상태에서의 원인 단정 전면 금지.
2. **고객 의사·시점의 확정화** — 입력에 없는 시점을 의사로 확정(GC-10 "63세 전까지"), 휴리스틱 분류의 사실화(GC-01 "선호 성향으로 분류되며"). 허용형: "~로 분류될 수 있다"(GC-02).
3. **조건부의 무조건화** — Action의 condition을 Brief에서 생략한 채 지시문으로 변환(GC-12 한도 조건 생략, GC-03 RUN_001 계열). Brief의 지시는 반드시 조건 절과 함께.
4. **Constraint 범위의 변형 재진술** — 허용/금지 등급을 원문과 다르게 축소·확대(GC-03 RUN_001).
5. **강화 수식어** — 입력에 없는 "강력히 선호" 류(GC-04 RUN_001).
6. **KPI성 분류의 압박 수단화** — TM 리스트·수익률 하위 분류를 고객 설득 근거로 쓰는 것(GC-04·GC-05가 이미 Brief에서 스스로 금지한 것을 Spec 차원으로 승격).
7. (기존 출력이 이미 지키고 있어 유지 강제) 비대면 특정 상품 권유·성과 보장 발언(GC-06), 성향 상한 초과 상품 권유(전 Case C1 PASS).

### (c) 완전 신규 제작 vs 재배치

**재배치만으로 충족되는 것** (구조화 판단부에 원재료가 이미 있음):

| 새 섹션 | 원재료 (현 출력 위치) | 필요 작업 |
|---|---|---|
| S1 고객 상황 | `current_situation` (§3) | 재배치 + 어휘 규칙(F-001 방지) 적용. 18/18 존재 |
| S2 핵심 관리 포인트 | `management_judgment.judgment` + `reasoning` (§6) | 재배치(요약) |
| S2 먼저 확인하세요 | `must_confirm` (§6) + `unknowns_or_confirmations` (§3) | 재배치 — REV-001 스키마는 이미 judgment에 종속. 고객 확인/직원 확인 구분 태그만 추가 |
| S3 추천 운용 방향 | `next_actions`의 kind=변경/유지/고객 결정 지원 항목 + condition + risk_level (§7) | 재배치 + 조건 보존 검증(F-008 방지) 신설. 연령·성향 고려는 reasoning에 이미 존재 |
| S4 중 접근 논리·설명 순서 | Brief 문단 내 순서 서술(GC-02·GC-05 등) + `next_actions`의 순서·condition | 재배치 + 순서 표기 표준화 |
| S5 중 업무 절차·제도 유의사항 | `next_actions`의 kind=절차/정보안내 항목(60일 기한, 창구 접수, DO 등록 vs 상품교체 구분 등), Brief의 금지 문구(비대면 권유 금지 등) | 재배치 + 출처 필드 추가 |

**완전히 새로 만들어야 하는 것** (현 출력 18개 어디에도 실질이 없음):

1. **S4 실제 화법** — 0/18. 직원이 그대로 쓸 문장 단위 스크립트는 스키마 필드도, 프롬프트 지시도, Knowledge 소스도 현재 없음.
2. **S5 Hot Tip** — 0/18. 행내 Hot Tip 자료와의 연결 자체가 Knowledge Pack 전달 구조에 없음.
3. **S5 반론 대응** — GC-16의 이탈 대응 논리 1건이 유사할 뿐, 명시적 반론-대응 쌍은 없음.
4. **S5 출처 표기 체계** — K-ID(내부 추적용)를 직원용 행내 자료 인용(화면번호·자료명·출처)으로 변환하는 매핑이 없음. 화면번호는 입력에 있을 때만 간헐적으로 통과(3/18)하고 Brief까지 생존은 1/18(GC-11).
5. **Brief의 섹션화된 출력 스키마** — 현 `employee_brief`는 단일 문자열. 5-섹션을 강제하려면 스키마 분해가 필요하며, 이는 동시에 F-001/F-008 검증(섹션별 원재료와의 대조 Validation — GC-03·GC-12 EVAL이 "Brief↔Candidate 대조 Validation 부재"로 이미 제안한 것)의 전제가 됨.
6. **S3 비해당 유형의 표기 규칙** — 중도인출/실행불가/이탈 사례에서 S3를 어떻게 채울지에 대한 정의(현재는 사례마다 임의 처리).
