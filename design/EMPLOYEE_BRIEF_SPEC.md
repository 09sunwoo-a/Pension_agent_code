## 1. 섹션별 명세

### S1. 고객 상황

- **정의**: 현재 데이터상 고객이 어떤 상황인지 핵심만 간결하게. 관리 포인트와 연결되는 사실을 **선택**해서 서술(데이터 전사가 아님). 절제된 해석 허용.
- **원재료**: `current_situation` (재배치) + Evidence Pack ①~③의 Calculated 상태값.
- **필수**:
  - Fact와 추론의 구분 유지 — 허용 문형 준거(실제 출력에서 채집): "~로 추론되나 확인되지 않았다"(GC-05), "~로 분류될 수 있다"(GC-02), "부합할 가능성이 높다"(GC-14), "결정하지 않은 상태"(Human 기획 예시).
  - 구조화 판단부의 Unknown이 S1 산문에서 사실로 승격되지 않을 것 — **F-001 5건(CASE_001·GC-01·GC-09·GC-10·GC-17) 전부 이 지점에서 발생**, S1의 1순위 규칙.
- **금지** (전부 실제 발생 사례):
  - 판정어 "방치" 및 동계열 단정 어휘 (CASE_001·GC-09·GC-17·GC-12 RUN_001) — DO 미적용·현금 보유의 사유가 미확인인 동안 전면 금지. 대체 어휘: "운용으로 연결되지 않은 상태", "적용예정일 경과·사유 미확인".
  - 고객 의사·시점의 확정화 (GC-10 "63세 전까지" — 부수 언급의 승격) / 휴리스틱의 사실화 (GC-01 "선호 성향으로 분류되며").
  - 강화 수식어 (GC-04 RUN_001 "강력히 선호").

### S2. 핵심 관리 포인트 (+ 먼저 확인하세요)

- **정의**: "그래서 이 고객에게 지금 무엇을 관리하는 것이 중요한가"에 대한 커밋. 바로 아래 **"먼저 확인하세요"** 블록으로 Required Confirmation을 종속 배치 — 확인은 관리 포인트 실행의 첫 행동이다.
- **원재료**: `management_judgment.judgment + reasoning`(요약 재배치) + `must_confirm_before_action`.
- **필수**:
  - 관리 포인트 1개(복수 이슈 시 우선순위 명시 후 주 포인트 1 + 부 포인트) + 근거 한 줄.
  - "먼저 확인하세요" 항목에 **[고객 확인] / [직원 확인(Operational Check)] 태그** — GC-07(페널티 규정)·GC-16(이전 가능 확정)이 직원 확인 유형의 실례.
  - **근거 출처 테스트 통과**: 포인트의 근거가 Customer Fact/Event에서 출발할 것. KPI·TM·캠페인 출발은 Critical(F-009).
  - 부차 시한 항목(Upcoming Events의 다른 만기 등)이 주 포인트에 가려 탈락하지 않을 것 — 부 포인트 또는 S5 후속관리로 반드시 수용(GC-09 1,500만 누락 대책).
- **Judgment 결과별 변형** (내부 라벨은 비노출, 포인트 서술로 번역):
  | 내부 판단 | S2 포인트의 형태 |
  |---|---|
  | 개입 필요 | "○○ 관리가 필요합니다" + 먼저 확인 + 확인 후 연결 |
  | 추가 확인 우선 | "이번 접점의 목적은 ○○ 확인입니다" — 확인 자체가 포인트 |
  | 현상유지 가능 | "현 운용 유지가 합리적입니다" + 다음 관리 시점(만기 D-30 등) 예약 — 유지도 관리다 |
  | 정보 안내 중심 | "○○ 제도 안내가 필요합니다" (권유 아님을 명시) |
  | 고객 결정 지원 | "선택지 정리와 상충관계 안내로 결정을 지원합니다" |
  | 실행 불가 | "요청하신 ○○는 현재 불가합니다 — 사유·충족 시점 안내가 포인트" |

### S3. 추천 운용 방향

- **정의**: 관리 포인트를 실제 운용방향·Solution으로 연결. 연령·자금 성격·예상 운용기간·투자성향·자산구성·고객 의사를 고려. 필요 시 상품 유형→상품 수준까지.
- **원재료**: `next_actions`(kind=변경/유지/고객 결정 지원)의 action+condition+risk_level (재배치) + Reference Data.
- **필수**:
  - **조건부 형식 강제**: 모든 방향은 "…이 확인되면 →" 조건 절과 함께. 확인 미완 사항의 무조건 지시 금지.
  - **분기 보존**(F-010 대책): 확인 결과에 따른 갈래를 최소 2개 유지(예: "장기운용 확인 → 운용 연결 / 단기 사용 예정 → 유동성 확보 경로"). 커밋은 포인트(S2)에서, 분기는 방향(S3)에서.
  - **Constraint 정확 재진술**: 성향 상한·허용 등급 범위를 Constraint 원문과 문자 대조(GC-03 RUN_001 축소 재진술 재발 방지). C1/C2/C3 validator의 검사 범위를 S3 텍스트로 확장.
  - **조건·제약의 변환 보존**(F-008 대책): Action의 condition·한도 개념(연금수령한도 등)이 S3 서술에서 탈락하지 않을 것(GC-12 잔존 사례) — 섹션별 원재료 대조 검증 대상.
  - 수치는 as_of 동반(특별제공 금리 등 — GC-08 재생산 실패 관찰). 최종 계산값은 HD-1대로 화면·계산기로 연결.
  - 상품 수준 연결 시: 성향 Eligibility 준수 + 채널 제약(비대면 특정 펀드 언급 유의) + "고객 본인 선택" 구조(GC-17 앱 검색 방식이 준거). ※ SYSTEM_ROLE 원칙 5 변경은 Step 3 승인 항목.
- **비해당 유형의 표기 규칙** (현재 Case마다 임의 처리 → 표준화):
  | 유형 | S3 표기 |
  |---|---|
  | 상품 권유 금지 사례 (GC-14 중도인출) | "이 상담에서 상품 권유는 하지 않습니다(사유)" 명시 후 섹션 종료 |
  | 실행 불가 사례 (GC-15) | 운용 방향 대신 "대안 경로 확인"(예: 연금저축 간 이전 가능성 확인 후 안내) |
  | 이탈 대응 사례 (GC-16) | 운용 방향 대신 "대안 제시"(손실 고지·비대면 전환 등) — 고객 결정권 명시 |

### S4. 상담 Point

- **정의**: 직원이 어떤 논리와 **순서**로 접근·설명할지 + 실제 고객 설명 문구.
- **원재료**: 접근 논리·순서는 기존 출력에서 재배치(GC-02 [확인→확인→제시], GC-05 "개시 요건 충족을 접점으로", GC-16 니즈 인정 논리). **화법 문장은 완전 신규(0/18)** — 스키마 필드·프롬프트 지시 신설 필요.
- **필수**:
  - 접근 순서 번호 목록 (형식 규칙: 화살표는 "→" 플레인 텍스트 — LaTeX 잔재 `$\rightarrow$` 재발 방지).
  - **실제 화법 최소 1개** — 고객에게 그대로 쓸 수 있는 문장. 공급원(SCREENS_HOTTIPS_INVENTORY §3): 용어 치환 사전(위험=변동성, 디폴트=기본값, IRP=바구니), 설명 순서 패턴(상태 인지→사용계획→대안; 세액공제→과세이연→유동성), 정직성 장치("손실 가능성과 확정 구분", "안 해도 된다고 말해주기"), 이탈 골격(인정→사과→대안→쿨링).
  - 단정·압박 회피 톤: 규모 축소+가역성("일부만, 되돌릴 수 있음"), 3인칭 인용, 조건부 권유.
- **금지**: KPI성 분류(TM·수익률 하위)를 설득 근거로 사용(GC-04/05가 스스로 지킨 것의 Spec 승격) / 근거 없는 비교·과장 / 용어 미치환("고유계정대"를 고객 화법에 그대로).

### S5. 관련 TIP & GUIDE

- **정의**: 행내 자료에서 이 Case에 도움이 되는 실무 재료를 **출처와 함께** 연결: Hot Tip·확인 순서·반론 대응·관련 화면·업무 절차·후속관리·제도 유의사항.
- **원재료**: 절차·유의사항 일부는 재배치(kind=절차/정보안내 Action). **화면번호 유지·Hot Tip 연결·출처 표기는 사실상 신규** — 현 K-ID 인용은 내부 추적용이지 직원이 찾아갈 수 있는 연결이 아님.
- **필수**:
  - 화면번호는 **[번호] + 화면명 + 한 줄 용도** 형식으로 최종 출력까지 유지 (GC-11이 유일한 성공 준거; GC-08 [04-12-642]·GC-16 [04-12-613]이 탈락 사례).
  - 출처 표기: 자료명 또는 SRC-ID + 권위 수준(공식 기준/행내 가이드/Hot Tip) — Hot Tip은 HD-3대로 "현장 노하우, 실행 전 공식 확인" 단서.
  - 시점 의존 수치(수수료율·금리·KPI 연도)는 as-of 명기; KPI 동기성 재료((f)군 9건)는 동기를 제거하고 절차만.
  - 후속관리 항목: S2에서 수용한 부차 시한(다음 만기·재점검 시점)을 여기서 구체화.
- **공급 판정** (인벤토리 §4): 이탈방어·과세이연/퇴직금·세액공제/개시·리밸런싱/DO·ISA만기는 재료 충분. **중도인출·상속/압류·공식 수수료율·연금수령 세부 세제는 빈약** → 빈약 영역 Case의 S5는 "관련 행내 자료 없음 — [화면/부서]로 확인" 명시(없는 팁 생성 금지가 이 섹션의 1순위 금지).
- **REV-002 공급 방식**: Case별 Knowledge Pack에 S5 재료(화면·Tip·출처)를 수동 동봉 — 색인 자동화·Retrieval은 §20.8대로 보류(TARGET_CONCEPT §6-6).

## 2. 스키마 방향 (구현 상세는 Step 4)

`employee_brief`를 단일 문자열에서 5개 필드(brief_s1~s5)로 분해. S2는 {포인트, 근거, 먼저_확인[{항목, 태그}]}, S3은 {방향[{조건, 내용, risk_level}] | 비해당{유형, 사유}}, S5는 {항목[{내용, 출처, as_of?}]} 구조 지향. 구조화 판단부(①~④)는 REV-001 스키마 유지(원재료 역할).

|---|---|---|

| V-형식 | 전체 | LaTeX 잔재(`$\rightarrow$` 등) 검출 |

## 4. 섹션별 평가 축 (Claude Evaluator — Regression에서 관찰)

- S1: 선택의 적절성(핵심 사실 누락 없음) / 어휘 절제 / Fact-추론 구분.
- S2: 포인트의 정당성(근거 출처)·우선순위 / 확인 항목의 완전성(F-004) / Judgment 유형과의 정합(특히 유지·불가 Case에서 개입 포인트를 만들어내지 않는가 — **F-005 재발 감지**).
- S3: 조건부 유지 / 분기 보존(F-010) / Constraint 정확성 / 비해당 유형 규칙 준수.
- S4: 순서의 논리 / 화법의 사용 가능성·톤(단정·압박 없음) / 용어 치환.
- S5: 실존 재료 여부(생성 금지) / 출처·as-of / 실무 유용성(F-007 계열).
