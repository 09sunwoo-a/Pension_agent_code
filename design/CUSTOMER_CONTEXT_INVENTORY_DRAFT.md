### 1.1 Cross-case 관찰 (Input 설계에 직접 영향)

1. **가장 많이 오판을 유발한 조합**: `현금성자산 비중 = Known` + `현금 발생 사유·경과일·사용계획 = Unknown` → "방치/미운용" 확정 (CASE_001, GC-12; GC-03은 발화가 있어 방지). **입금 사유·입금 경과일**이 없으면 Agent는 채워 넣는다.
2. **Customer-stated의 시점(Freshness)이 판단을 바꾼다**: GC-04(6개월 전), GC-06(8개월 전+이후 매매), GC-03(개설 시). 발화 일자와 이후 이벤트가 있어야 "재확인 필요" 판단이 가능하다.
3. **고객 발화 속 부수 언급을 의사로 승격**: GC-10 "국민연금 63세" → IRP 개시 63세. 발화는 원문(또는 요약)과 함께 **어디까지가 확인된 의사인지**가 구분돼야 한다.
4. **시계(Clock) 계산을 LLM에 맡기면 틀린다**: GC-04 "입금 23일 + DO 등록 → 2주 자동적용 이미 도과"를 RUN_001은 놓침. 만기 D-n, DO 적용 예정일, 개시요건 충족 여부 같은 **Derived Fact는 시스템/전처리에서 계산해 주는 편이 안전**.
5. **Marketing/Target 분류가 Fact와 같은 자리에 오면 근거로 오용**(F-009). TM 리스트 포함 여부는 "왜 이 고객이 지금 화면에 떴는가"의 Trigger Provenance이지 Customer Fact가 아니다.
6. **입력에 있어도 관련도 단서가 없으면 미사용**(F-003): 스타뱅킹 이용(채널), 입금예정상품 미등록, LMS 발송 — 모두 "실행·채널·고객 인지" 관련 Fact. 이들은 판단보다 **Next Action 단계**에서 필요한 정보라는 점이 공통.
7. **반복 누락된 확인 축**(F-004, 5/8): 만기 길이 선호 · 채널 선호(비대면/내점) · 직접/위임 선호 · 결정 시한 · 재취업/추가납입 계획 · 핵심 사유 강도 · DO 미등록 인지. 시스템에 없고 상담에서만 확인 가능한 "Consultation-time Confirmation" 후보.
8. **직원 화면 조회값**은 Agent 입력이 아니라 Next Action 산출물: 특별제공 금리·한도 [04-12-17A], 수수료율 [04-12-613], 연금수령한도·최소수령기간 [02-12-221], 세액미공제 [06-12-622], 입금사유 [04-12-644], 환급 처리 상태, 중도해지 손실 계산기. HD-1(계산값 Scope 밖)과 정합.
